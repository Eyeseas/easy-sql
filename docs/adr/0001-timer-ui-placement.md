# 计时器 UI 按页面场景分布，全局底栏仅作跨页兜底

计时状态是全局单例（同一时刻只有一个学习日在计时），早期据此把计时 UI 做成了唯一的固定底栏，结果周页点「开始今天」后计时器与当天的卡片失去视觉关联。决定：计时 UI 拆成场景化的两个呈现位——周页嵌进 DayCard 卡片内、天页放进右栏；全局底栏降级为兜底，仅当进行中的会话不属于当前页面时出现。

## Considered Options

- 全站右侧悬浮部件：与周页/总览的内容抢宽度，且周页真正需要的是卡片内就近呈现，被否。
- 每张卡片独立计时（多会话）：与课程叙事「一天 2 小时、一天一段剧情」冲突，通知/标题/状态管理复杂度翻倍，被否。计时会话保持全局单例。

## Consequences

- 计时中的会话在「本页有该天但卡片滚出视口」时不可见--接受此不完美，标签页标题常驻剩余时间兜底。
- 底栏组件保留但常态隐藏；若未来出现第四个页面类型，兜底条件需重新审视。
- 兜底横条内部直接渲染共享的运行位部件（TimerWidget），全站只有一份内容结构；三段进度的填充机制也只定义在部件内，不进全局 CSS。
- 完课提示（三段跑完后的「标记完成 / 还没」横条）保持全局固定条：它是独立的一次性强提醒，不属于兜底横条，也不随呈现位内联。
- 多标签页不做同步，localStorage 谁最后写谁赢--单人学习工具的罕见路径，接受。
- 周页部件插在卡片标题行与详情区之间（不进 .detail）：精简视图折叠详情时运行中的部件仍然可见。
- 天页呈现位是天页专属的右栏区块（部件 + SidePanel 同一个 sticky 容器）；SidePanel 三页共用，不放计时器。
- ≤1100px 窄屏下 aside 列沉到主内容下方，天页部件随之不可见--接受，与「卡片滚出视口」同级的不完美，标签页标题兜底。
